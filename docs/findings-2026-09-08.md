# herdr 0.9.0 实测（2026-09-08）

环境：herdr 0.9.0（homebrew-core，2026-09-07 发布；0.8.2 之后没有中间版本）、Claude Code 2.1.263、
隔离 session `herdgentdev`（AGENTS.md 的开发配方），只碰自己建的 workspace。
脚本与原始日志在会话临时目录，不入库；下面是结论与证据。

## 一、三条契约，全部命中

| 契约 | 命令 | 观测 |
|---|---|---|
| `agent prompt` 自带 Enter | idle 时 `agent prompt <pane> "…"`，**不**补 `send-keys enter` | 4/4 次 seq 立即 +1、状态 idle→working→idle，屏幕上该轮跑完。0.7.5 时代「claude 只输入不回车」的前提已被上游修掉（#3506/#3685，"honors bracketed-paste, sends text then Enter as one ordered submission"） |
| blocked 时拒收 | AskUserQuestion 弹出后 `agent prompt <pane> hello` | `{"error":{"code":"agent_blocked","message":"agent w3:p1 is blocked and requires interactive input"}}`，exit 1，seq 不变 |
| 启动期 blocked | opening prompt 直接触发 AskUserQuestion，`agent start … -- claude "…"` | 11s 后 `{"error":{"code":"agent_not_ready","message":"agent hg090d is blocked during startup and is not ready for prompts"}}`；此时 `agent get` 正常返回：`agent_status: blocked`、`agent_session` 已有、多了一格 `launch_pending: true` |

解锁路径（同一轮实测）：

- `agent send-keys <pane> enter` 选中高亮项 → blocked→working→idle，1–2 秒。
- `pane send-text <pane> "<text>"` + `agent send-keys <pane> enter` 在 idle 时能提交一条 prompt（seq +1、进入 working）——
  这是绕过 `agent_blocked` 守卫的打字路径；对话框需要自由文本时用它。
- **对选项框发文字没有用**：AskUserQuestion 弹着时 `send-text "Blue"` + enter，选中的是高亮项 Red，文字被忽略。
  选项一律走 keys；text 只给真有输入框的对话框。
- **启动期 blocked 是一场竞态**：同一条「立刻 AskUserQuestion」的 opening prompt，一轮 11s 后报 `agent_not_ready`，
  另一轮连续三次 3s 内就返回 idle（herdr 先判到就绪，弹框在后）。两条路生产里都会出现：idle 路径下弹框随后由
  `wait_for_worker` 以 blocked 报出；not_ready 路径由 `startAgentWhenReady` 接住。

用改后的真实代码（`startAgentWhenReady` + `sendAndConfirm`）在同一隔离 session 联调一遍：

| 步 | 调用 | 结果 |
|---|---|---|
| 启动期 blocked | `startAgentWhenReady([...opening prompt 立刻弹框])` | 返回 `recovered: true, blocked_at_startup: true`，agent 为 blocked |
| 选项解锁 | `sendAndConfirm(pane, null, { keys: ["down","enter"] })` | `submitted: true, delivery: keys`，随后 idle |
| 普通派活 | `sendAndConfirm(pane, "Reply PONG")` | `submitted: true, delivery: prompt` |
| blocked 时送文字 | `sendAndConfirm(pane, "Blue")` | `submitted: true, delivery: send_text`（但见上：选项框只认高亮项） |

联调顺手抓到一个真 bug：`pane send-text` 成功时 **stdout 为空**，`herdr()` 封装把它判成 `bad_output`；已改走 `herdrText`
（只认 stderr 信封与退出码），单测的假 herdr 也按空输出来。

`agent prompt --wait` 新增的 `agent_prompt_stalled`（从非 working 发出须 5s 内看到 working/blocked）与 herdgent 无关：
herdgent 不用 `--wait`，自己轮询 `state_change_seq`。

## 二、没能复现的两个界面

| 想逼出 | 做法 | 结果 |
|---|---|---|
| 目录信任框 | 全新目录 + `--permission-mode default` | Claude Code 2.1.263 直接进入会话，没有信任框。`agent_not_ready` 改用「opening prompt 立刻 AskUserQuestion」复现 |
| Bash 审批框 | `--permission-mode default` 下让它跑 `ls -la` | 直接放行，没弹框。原因待查（可能是全局 allow 规则或只读命令免批），与本次无关 |

顺带看到的一条：`~/.claude/settings.json` 里 `permissions.defaultMode = "bypassPermissions"`。herdgent 给 claude 的
`--settings` 是**合并**语义，所以在这台机器上**「非 yolo」的 claude worker 实际也是 bypass**——只读档靠的是工具黑白名单，
不靠审批门，这条边界仍成立；但 profile 里 `yolo: false` 对 claude 并不构成第二道门。

## 三、跟进的改动

| 处 | 之前 | 现在 |
|---|---|---|
| `lib/worker.mjs` `sendAndConfirm` | prompt 后按 `submitNeedsEnter` 补 enter | 只发 prompt；`agent get` 已 blocked 或 prompt 回 `agent_blocked` → `pane send-text` + `send-keys enter`；新参数 `keys` 只发 `send-keys`；返回多一格 `delivery`（prompt / send_text / keys）；text 与 keys 都没有则拒绝 |
| `lib/herdr.mjs` `startAgentWhenReady` | 只把 `agent_pane_busy` 当可恢复，`agent_not_ready` 上抛成启动失败并回收 workspace | `agent_not_ready` → `agent get` 拿到 kind 相符且 blocked 的 agent 就当起来了，返回带 `blocked_at_startup: true`，不重试；此时允许没有 `agent_session` |
| `lib/harness/*.mjs` | 三家各有 `submitNeedsEnter` | 删掉；提交语义不再按家分支 |
| `bin/mcp-server.mjs` `send_to_worker` | 只有 `text` | `text` / `keys` 二选一；描述写明 blocked 时不经守卫、先看屏幕 |
| `skills/rex`、`skills/fox` | 「用 `send_to_worker` 答」 | 选项走 `keys`，打字走 `text`，答前必须先 `read_worker mode=screen` |
| `herdr-plugin.toml`、`bin/install.mjs` | 下限 0.8.0 | 0.9.0 |
| `lib/events.mjs` | 注释停在 0.7.5 | 按 `herdr api schema --json`（protocol 22，0.8.0 时是 19）对过账：订阅形状未变；新订阅不回放历史，onReady 补查不能省 |

新测试：`test/send-and-confirm.mjs`（投递路径）、`test/start-not-ready.mjs`（启动回答分支）。

## 四、其它观察

- `workspace create --cwd <不存在的目录>` 不报错，静默回落到 `$HOME`。herdgent 传的 cwd 都是刚建出的 worktree，
  不会撞到；手工实验容易撞。
- `agent start` 在 0.9.0 下 3 秒返回（claude 起得快），`agent prompt` 服务端约 300ms 完成提交确认。
- `workspace close` 对含 worktree 子 workspace 的**主** workspace 现在要 `--group`；herdgent 只关自己建的子 workspace，不受影响。
