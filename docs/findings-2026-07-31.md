# herdr 0.7.5 实测记录（2026-07-31）

> 全部为**实测**，非推断。环境：macOS，herdr 0.7.5（2026-07-21 发布），Claude Code（Opus 5），omnigent 0.7.0。
> 易变——herdr 迭代很快，`[[startup]]` 与整套 `agent start/prompt/wait` CLI 都是 0.7.5 才加的。**引用前先复核。**

## 一、herdr 能无头驱动（这是 herdgent 成立的前提）

零客户端 attach 的情况下走通：`workspace create` → `tab create` → `agent start --kind claude --pane` → 提交 → 观测 → `agent read`。`agent start` 约 3 秒返回 `interactive_ready: true`。

## 二、状态观测的三个坑

1. **裸跑 `claude` 落在会话面板首页，不是一个会话。** 在那个界面上 `agent prompt` 的文字**会被真提交**（任务确实执行并出现在面板的 Completed 列表），但 herdr 完全观测不到，报 `agent_prompt_stalled`、status 恒为 `idle`。
   → **编排层会以为什么都没发生，实际有会话在无人看管地跑。** 解法：`agent start … -- "<初始 prompt>"` 直接进会话。
2. **`herdr agent prompt` 只输入不回车**（这版 Claude Code 的会话 TUI 上）。屏幕实证：文字停在输入框里。必须补 `agent send-keys <target> Enter`。
3. **终态是 `done` 不是 `idle`。** `agent wait --until idle` 会一直等到超时（实测等满 2 分钟）。
   → 可用循环：记下提交前的 `state_change_seq`，提交后轮询 `agent get` 直到 seq 变化**且** status ∈ {done, idle, blocked}（实测 3.3 秒收敛）。`agent wait` 没有 "since seq" 参数，去重必须自己做，否则会拿到上一轮的终态立即返回。

> 更正一处早期判断：herdr 的观测层不弱，但它按「一个 pane 一个前台会话」建模；当 harness 自己也变成会话管理器（Claude Code 的面板首页）就失灵。

## 三、重启只恢复布局，不恢复运行时 ⚠️ 最重要

| | 结果 |
|---|---|
| workspace id、`custom_name`、pane id、cwd、布局 | ✅ 存活（`session.json` 持久化） |
| `terminal_id` | ❌ 每次必变 |
| pane 里的 agent 进程 | ❌ 全被杀（server 日志 shutdown 时 `pane child exited`） |

**恢复出来的记录是幽灵**：`agent list` / `agent get` 仍报该 agent 为 `agent_status: idle` + `interactive_ready: true`，还带着旧的 `agent_session` UUID；而同一个 `pane_id` 在 `pane read` / `pane process-info` 下是 **`pane_not_found`**，`agent read` 是 `agent_not_found`。

→ **pane 侧是权威，agent 侧不是。** `bin/reconcile.mjs` 就是为此存在（实测：重启后 herdr 报 3 个 agent 全 idle，对账正确判死）。

## 四、ID 不可作主键

`HERDR_WORKSPACE_ID=w6`（pane env 注入）在同一会话存续期间就已失效——`workspace get w6` 返回 `workspace_not_found`，同一会话此时是 `wX`。`terminal_id` 重启必变。
→ 主键只能用 **harness 侧 session id**；`custom_name`（`--label`）会持久化，可作可恢复的归属标记。

## 五、环境变量是双向泄漏的

- **从 pane 里起 herdr server 会继承 `HERDR_SOCKET_PATH`**，于是"隔离实验"实际连回了 default 会话。起隔离 server 前必须 `env -u HERDR_*`。
- **server 会把自己的环境传给它起的每个 pane，再传给每个 agent。** 实测症状：被起的 claude 状态栏出现「⚠ Transcript saving is off — inherited CLAUDE_CODE_…」，会话标题串成父会话的名字。
- **反过来不通**：`HERDR_PLUGIN_STATE_DIR` 只注入插件命令，**不会传进插件启动的会话**。所以钩子必须靠显式 argv 接力状态目录（`--state-dir`）。

## 六、Claude Code `--settings` 是【合并】语义 ✅

实测双向确认：注入的 `SessionStart` 钩子执行了（marker 落盘），**同时** herdr 自己的 `SessionStart` 钩子也执行了（`agent_session.source = herdr:claude` 被填）。
→ **控制面可以经启动 argv 注入，不会把 herdr 弄瞎。** 这是 herdgent 全部设计的地基，改动注入逻辑前先复验这条。

## 七、写代码时撞到的（真机三次失败）

1. **herdr 的错误信封走 stderr、结果走 stdout。** 只读 stdout 会把合法错误误判成"输出损坏"。
2. **agent 名有约束**：小写字母开头，只含 `[a-z0-9-_]`，1–32 字符。ISO 时间戳（带大写 T/Z）直接被拒。
3. **`workspace create` 返回时 pane 还没到交互提示符**，紧接着 `agent start` 报 `agent_pane_busy`（"not an available shell"）。而且**判据不是"shell 进程存在"**——进程早就在了、屏幕上也已有提示符，herdr 仍可能说不可用。
   → 不要猜它的判据，按它的回答重试（`startAgentWhenReady`）。
4. **起 agent 失败会漏下一个空 workspace**，必须回收，否则每次失败都在用户界面里留个空壳。
5. **SessionStart 钩子在 `agent start` 执行期间就回调**——登记必须**先于**起 agent 写入，否则钩子查无此键，session id 就丢了。

## 八、herdr plugin 契约（0.7.5）

manifest 是仓库根的 `herdr-plugin.toml`：必填 `id` / `name` / `version` / `min_herdr_version`；可声明 `[[actions]]`、`[[events]]`、`[[startup]]`、`[[panes]]`（placement: overlay/popup/split/tab/zoomed）、`[[link_handlers]]`（正则 + Ctrl+click）、`[[build]]`、`[[keys.command]]`。

命令一律 **argv 数组、无 shell 展开**，注入：`HERDR_SOCKET_PATH` / `HERDR_BIN_PATH` / `HERDR_ENV` / `HERDR_PLUGIN_{ID,ROOT,CONFIG_DIR,STATE_DIR}` / `HERDR_PLUGIN_CONTEXT_JSON`（workspace/tab/pane/worktree/agent/选中文本/URL），以及按类型的 `HERDR_PLUGIN_{ACTION_ID,EVENT,EVENT_JSON,ENTRYPOINT_ID,CLICKED_URL}`。

文档原话：**「The entire Herdr CLI is the plugin API」**。

事件共 25 种可订阅（`events.subscribe` / `events.wait`），含 `pane.agent_status_changed`、`pane.agent_detected`、`pane.output_matched`、`pane.exited`——**编排可以事件驱动，不必轮询**。

插件安装自 0.7.5 起是**用户全局**的，不再按 herdr session 隔离；`plugin link --disabled` 可先挂不启用；config/state 目录按 plugin id 分。

## 九、omnigent 对照（决定要建多少）

| | herdr 观测层 | omnigent 控制面 |
|---|---|---|
| claude | 101 行 (sh) | 17,551 行 |
| codex | 92 行 (sh) | 13,048 行 |
| pi | 395 行 (ts) | 2,641 行 |

但 omnigent 那 33k 行里 **`*_forwarder` 占 12,372 行，作用是把 transcript 增量重建给它的 web UI**——herdgent 让 herdr 当前端，这块整块蒸发，只需保留其中的成本计算。

另：omnigent 的 bridge 文档写明它**也是靠往 pane 里 send-keys 提交**的，所以第二节那个提交坑两边同源。

许可：herdr 是 **AGPL-3.0-or-later**（`github.com/herdrdev/herdr`），omnigent 是 **Apache-2.0**。Apache→AGPL 单向可并入，反之不行；herdgent 取 Apache-2.0 并只经 CLI/socket 与 herdr 交互。
