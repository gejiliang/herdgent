# herdr 0.8.0 实测记录（2026-08-05）

> 全部为**实测**，非推断。环境：macOS，herdr 0.8.0（brew，License: Apache-2.0）。
> 与 [`findings-2026-07-31.md`](findings-2026-07-31.md)（0.7.5 时代）并用；那篇里没有被本篇覆盖的结论仍有效。**引用前先复核。**

## 一、许可证：herdr 自 0.8.0 起改为 Apache-2.0 ⚠️ 旧表述全部失实

已从上游 repo `herdrdev/herdr` 的元数据确认，不只是 changelog 措辞；本机 `brew info herdr` 同样显示 `License: Apache-2.0`。

- **0.8.0 之前**的 herdr 仍然是 AGPL-3.0-or-later。引用旧版本时按 AGPL 对待。
- herdgent 与 herdr 现在**都是 Apache-2.0**，「herdr 的代码不得并入本项目」这条法律约束**已不成立**。
- herdgent 自己取 Apache-2.0 的**原始理由不变**：可以合法吸收 omnigent（Databricks, Apache-2.0）的实现思路与代码。
- **不 fork herdr 的结论不变**——理由从来都是工程成本（herdr 快速迭代，fork 长期 diverge，plugin 可分发），许可证只是曾经附带的一层约束。现在这层没了，不 fork 是**纯工程判断**。见 `AGENTS.md` 形态纪律。

## 二、两个新的可观测面（0.8.0 新发现，此前文档完全没提）

### `herdr api schema` —— socket API 的权威契约

- `herdr api schema` 给摘要，`herdr api schema --json` 给完整 JSON（约 251KB），`--output PATH` 可落盘。
- 摘要里带 **`protocol: 19`** 协议版本号。
- 价值：`lib/events.mjs` 里的事件协议形状目前完全靠实测注释固化，现在有权威来源可以对账；`protocol` 号也比 `herdr-plugin.toml` 里 `min_herdr_version` 的字符串比较更硬。

### 对账实例：`agent.read` 的参数契约（已对着 schema 核对）

新增的 socket 读取路径的参数形状，已用 `herdr api schema --json` 独立核对过（此前只对着测试自建的 fake server 验过，而 fake 不校验参数）。以下为 schema 原文：

**请求 `agent.read` → `AgentReadParams`**

| 字段 | 类型 | 约束 |
|---|---|---|
| `target` | string | **required** |
| `source` | ReadSource | **required**，枚举 `visible` / `recent` / `recent_unwrapped` / `detection` |
| `format` | ReadFormat | 默认 `text` |
| `strip_ansi` | boolean | 默认 `true` |
| `lines` | integer \| null | — |

**应答 → `PaneReadResult`**，required 字段：`pane_id`、`workspace_id`、`tab_id`、`source`、`format`、`text`、`revision`、`truncated`。

判据：`truncated` 是 **required** 的，所以它只会在协议本身变更时缺失——`bin/mcp-server.mjs` 里那个 `typeof` 守卫和随后的降级不是防御正常情况，是防御协议变更，两条降级路径现在都会 `log()` 留痕（见 commit `97e9f27`、`9c6116e`）。

### `herdr plugin log list` —— 插件命令的执行日志

带 `command` / `event` / `exit_code` / `status` / `stdout` / `stderr`。

- 价值：`[[startup]]` 钩子（`node bin/reconcile.mjs`）跑在 herdr 启动路径上，出问题时这是**唯一**能看到它 stdout 和退出码的地方。
- 实测确认 reconcile 在 0.8.0 下跑通：`exit_code: 0`，stdout `herdgent: no active sessions, nothing to reconcile`。

## 三、两个被否掉的「坑」（看起来像，实际不是）

- **`herdr plugin` 子命令仍然存在**，只是**不出现在顶层 `herdr --help` 的摘要里**——照着顶层 help 会误以为它被删了。`install.mjs` 的 `plugin link` / `unlink` 没断。
- **`herdr worktree` 命令是 JSON-only**：0.8.0 把冗余的 `--json` 旗标从 help 和文档里撤了，但**仍然接受**它以保持兼容。我们本来就没传，不受影响。
