# herdr 0.9.1 影响评估（2026-09-17）

## 结论与证据边界

- CLI 与运行中 default server 均为 0.9.1；`herdr status server`：endpoint/private protocol compatible，protocol 22。
- 上游 v0.9.0...v0.9.1 diff、release notes 与本地调用点交叉检查：未发现 herdgent 当前本机路径需要紧急适配的破坏性变更。
- 0.9.0 发布 schema 对比 `herdr api schema --json`：protocol 均为 22；request 新增 pane.link.resolve，success 新增对应结果与 PaneLinkRegion；既有 request 定义、事件/error/subscription schema 未变。
- `HERDR_SOCKET_PATH=/tmp/herdgent-audit-no-server.sock npm test` 完整通过。主要是 mock/本地测试，不证明真实 harness 端到端行为；本次未启动 worker、未重启服务、未安装代码。

## 影响映射

| 上游变化 | herdgent 影响 |
|---|---|
| Claude Unicode spinner、Pi working border、Codex 静态标题/排队输入/旧审批文字识别 | 改善 worker 状态与等待可靠性；不能替代 harness session/model 身份核对，不能删 blocked/启动恢复保护 |
| 临时进程检测失真时保留 agent 名 | 减少寻址抖动；pane/session 身份与启动对账仍需保留 |
| worktree 部分删除失败可重试、submodule 强制删除确认 | 有利于 finalize 重试；现有路径已用 --force，不能因此取消 dirty/merge/ownership 检查 |
| worktree create 恢复聚焦 | 创建路径已有 --no-focus，预期不抢焦点；真实并发回归待做 |
| pane split 默认调用 pane、focus/move 修复 | split 显式传 paneId，不依赖默认目标；未发现需要适配 |
| plugin 兼容 binary、registry symlink、focus events 修复 | lib/herdr.mjs 已读取 HERDR_BIN_PATH，直接受益；MCP 长进程不会因更新自动重载 |
| terminal observer 写不动 30s 后断开 | 是终端输出 observer，不是“所有空闲 socket 30s 超时”；不能据此改 events.subscribe 或添加无根据心跳 |
| --machine 远程 CLI | 只是未来能力入口。lib/events.mjs 裸连本机 Unix socket；registry、本地 git/fs 与路径也是本机语义。禁止仅给 CLI 加 --machine 就宣称远程编排可用 |
| macOS 服务跨 logout 修复 | 仅新启动 server 修复继承环境；live handoff 不修旧服务上下文。仅知道版本不能证明曾完整重启；无症状不为本次评估强制中断会话 |
| Windows Codex 提交修复、OpenCode V2、Letta | 当前本机 macOS 主路径不直接需要改造；新增 herdr kind 不等于 herdgent 已支持对应 harness |
